# Архітектура StudySwap

Діаграма: `architecture_diagram.drawio` (файл відкривається на app.diagrams.net) та експорт `architecture_diagram.png`.

## Загальна схема

```
Client (браузер)  <-- HTTP / JSON -->  Backend (Express REST API)  <-- SQL -->  Database (SQLite)
                                              |
                       майбутні модулі: Auth, Materials & Search, File Storage,
                       Comments, Complaints & Moderation, Notifications
                                              |
                              зовнішні сервіси: Email Service, AI Assistant
```

Суцільна рамка на діаграмі — основа системи, пунктирна — майбутні модулі та зовнішні сервіси.

## Що означає кожен блок

| Блок | Що робить |
|---|---|
| **Client (браузер)** | Сторінки на HTML/CSS/JS: головна, пошук, сторінка матеріалу, форма додавання, профіль. Показує дані користувачу й надсилає запити до API через `fetch`. |
| **Backend (Express REST API)** | Сервер на Node.js. Приймає запити від клієнта, перевіряє права за роллю, виконує бізнес-логіку й повертає відповідь у форматі JSON. Структурований за шарами: `api/` (роути), `service/` (логіка), `domain/` (сутності). |
| **Database (SQLite)** | Зберігає користувачів, матеріали, коментарі та скарги. Backend звертається до неї SQL-запитами. |
| **Materials & Search** | Каталог матеріалів: пошук за назвою, предметом, курсом, університетом і типом, фільтри, сортування, додавання, редагування та видалення матеріалів. |
| **Auth** | Реєстрація, вхід і вихід, хешування паролів, видача токенів JWT, розрізнення ролей «Гість», «Користувач», «Адмін». |
| **File Storage** | Приймає файли матеріалів, перевіряє їхній тип і розмір, зберігає й віддає їх користувачам. |
| **Comments** | Додавання та перегляд коментарів під матеріалом. |
| **Complaints & Moderation** | Подання скарг, їх перегляд адміном, блокування порушників, видалення матеріалів. |
| **Notifications** | Сповіщення про нові коментарі та результат розгляду скарги (спливне вікно за кнопкою сповіщень). |
| **Email Service** | Зовнішній сервіс відправки листів, потрібен для скидання пароля. |
| **AI Assistant** | Зовнішнє AI API: помічник, що допомагає шукати матеріали й відповідає на навчальні питання. Ключ API зберігається лише на сервері. |

## Приклад шляху запиту

Користувач вводить «нормалізація» й натискає «Знайти»:

1. Client надсилає `GET /materials?q=нормалізація&course=2`.
2. Backend перевіряє параметри й передає запит у модуль Materials & Search.
3. Модуль робить SQL-запит до Database.
4. База повертає рядки, Backend формує JSON і відправляє його клієнту.
5. Client показує картки матеріалів.
