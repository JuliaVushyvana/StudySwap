# ADR-0005. Рівні доступу: гість, користувач, адмін, суперадмін

- **Статус:** прийнято
- **Дата:** 2026-11-22

## Контекст

Після реєстрації та входу (JWT, PR #20) система знає, хто робить запит. Потрібно чітко визначити, що дозволено кожному. До цього перевірки прав були розкидані: `user.isAdmin()` у домені,
`requireUser` у сервісі, а `GET /materials/{id}` був відкритий для всіх.

## Рішення

Одна матриця прав у `backend/domain/access/permissions.js` (модуль `access`). Інші модулі отримують її лише через
публічний інтерфейс модуля — `accessPolicy` з `service/access/accessService.js` (ADR-0001, ADR-0002):
`app.js` передає `accessPolicy` у `materialService` і `storageService`, а ті питають `can(user, permission)` і
`canManageMaterial(user, material, 'update' | 'delete')` замість перевірки ролей вручну.

| Дія | Гість | Користувач | Адмін | Суперадмін |
|---|:---:|:---:|:---:|:---:|
| Бачити каталог — `GET /materials` | ✅ | ✅ | ✅ | ✅ |
| Відкрити сторінку матеріалу — `GET /materials/{id}` | ✅ | ✅ | ✅ | ✅ |
| Додати матеріал — `POST /materials` | ❌ 401 | ✅ | ✅ | ✅ |
| Змінити / видалити свій матеріал | ❌ 401 | ✅ | ✅ | ✅ |
| Змінити / видалити чужий матеріал | ❌ 401 | ❌ 403 | ✅ | ✅ |
| Завантажити файл — `POST /files` | ❌ 401 | ✅ | ✅ | ✅ |
| Переглянути PDF / Word / TXT на сайті — `GET /files/{id}/preview` | ✅ | ✅ | ✅ | ✅ |
| Скачати файл — `GET /files/{id}` | ❌ 401 | ✅ | ✅ | ✅ |
| Писати коментарі (модуль обговорення — пізніше) | ❌ | ✅ | ✅ | ✅ |
| Свій профіль — `GET/PATCH /users/me`, зміна пароля | ❌ 401 | ✅ | ✅ | ✅ |
| Розглядати скарги, блокувати (Пізніше) | ❌ | ❌ | ✅ | ✅ |
| Бачити користувачів і призначати / знімати адмінів — `GET /users`, `PATCH /users/{id}/role` | ❌ 401 | ❌ 403 | ❌ 403 | ✅ |

- **Гість** — немає токена, токен недійсний або користувача заблоковано.
- **Суперадмін** — четверта роль (додана 2026-11-22): усі права адміна + призначення адмінів. Обмеження: призначити можна
  лише `user` або `admin`; суперадміна призначити не можна, свою роль і роль іншого суперадміна змінити не можна.
  Тестовий акаунт `superadmin` створюється автоматично (`seed.js`, крок `ensureSuperAdmin`).
- **Зміна 2026-11-22:** гість бачить сторінку матеріалу і переглядає PDF / Word / TXT прямо на сайті, але не скачує
  файл і не коментує. Перегляд іде через окрему адресу `/preview`; PDF показується без панелі переглядача, Word
  малюється на сторінці. Повністю заборонити збереження показаного в браузері неможливо, це лише ускладнення.
- **401** — потрібно увійти; **403** — увійшли, але прав недостатньо.
- Роль береться з БД за `userId` з токена, а не з тіла запиту: підробити роль не можна.

## Фронтенд

`frontend/lib/permissions.js` повторює матрицю лише для зручності: ховає кнопки, яких користувач не має права натискати,
і перекидає гостя на вхід. Захист забезпечує бекенд: навіть якщо змінити фронтенд, сервер поверне 401/403.

## Наслідки

- Нове правило доступу — один рядок у матриці й тест у `test/access/permissions.test.js`.
- Модерація (скарги, блокування) вже має права `report:review` і `user:block`; їх використають, коли з'являться ендпоїнти.
