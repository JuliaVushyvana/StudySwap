### 4. Функціональні вимоги

Шаблон: Як [роль] хочу [дія], щоб [цінність]. Acceptance criteria (AC): Given / When / Then. Кожна вимога містить AC, помилкові сценарії та очікувані статус-коди.

Пріоритети: **MVP** — обов'язково для першої версії; **Пізніше** — планується на наступних етапах.

Коди відповідей: 200 — успіх; 201 — створено; 204 — виконано без тіла відповіді; 400 — некоректні дані; 401 — користувач не увійшов; 403 — недостатньо прав; 404 — не знайдено; 409 — конфлікт (дані вже існують).

**1. РЕЄСТРАЦІЯ** (MVP)

Як гість хочу зареєструватися, щоб додавати матеріали й коментарі.

AC:
- Given nickname 3..30 і login 3..30 (унікальні), коректний email, password >= 8, birthDate у минулому
- When POST /auth/register
- Then 201 + акаунт із роллю «Користувач»

Errors: 400, 409

**2. ВХІД І ВИХІД** (MVP)

Як користувач хочу увійти за логіном і паролем або через пошту, а також вийти з акаунта, щоб користуватися своїм профілем.

AC:
- Given правильні login (або email) і password
- When POST /auth/login
- Then 200 + токен доступу

AC:
- Given активна сесія
- When POST /auth/logout
- Then 204, користувач стає гостем

Errors: 400, 401

**3. СКИДАННЯ ПАРОЛЯ** (MVP)

Як користувач хочу скинути пароль через пошту, щоб відновити доступ до акаунту.

AC:
- Given email, зареєстрований у системі
- When POST /auth/password-reset
- Then 200 + на пошту надходить одноразове посилання для нового пароля

Errors: 400, 404

**4. РОЛІ ТА ПРАВА ДОСТУПУ** (MVP)

Як власник платформи хочу, щоб дії залежали від ролі («Гість», «Користувач», «Адмін»), щоб гості не могли змінювати дані.

AC:
- Given роль відвідувача (гість, користувач або адмін)
- When запит до захищеної дії
- Then дія виконується лише якщо роль має право згідно з матрицею доступу

Errors: 401, 403

**5. ГОЛОВНА СТОРІНКА** (MVP)

Як відвідувач хочу бачити головну сторінку з меню та новими матеріалами, щоб швидко почати пошук.

AC:
- Given будь-який відвідувач
- When GET /materials?sort=new&page=1
- Then 200 + items + total + page (блок рекомендацій) і меню: пошук, додати матеріал, сповіщення, вхід/реєстрація, вікно акаунту

Errors: 400

**6. ПОШУК МАТЕРІАЛІВ** (MVP)

Як студент хочу шукати матеріали за назвою, предметом, курсом, університетом і типом в одному пошуку, щоб швидко знайти потрібну шпаргалку чи відповідь.

AC:
- Given запит q до 100 символів
- When GET /materials?q=
- Then 200 + items + total + page (порожній список, якщо нічого не знайдено)

Errors: 400

**7. ФІЛЬТРИ ТА СОРТУВАННЯ** (MVP)

Як студент хочу фільтрувати й сортувати результати, щоб швидко знайти потрібні матеріали.

AC:
- Given university / subject / course / type / sort (new або title) / page
- When GET /materials
- Then 200 + items + total + page; за замовчуванням спочатку нові, за назвою — А-Я

Errors: 400

**8. ДОДАВАННЯ МАТЕРІАЛУ** (MVP)

Як користувач хочу додати матеріал, щоб інші студенти могли ним скористатися.

AC:
- Given title 1..200, subject, university, course, type (конспект, лекція, практична, лабораторна, презентація, відео, аудіо, курсова, дипломна, магістерська), description до 2000 символів і файл допустимого формату та розміру
- When POST /materials
- Then 201 + матеріал з'являється в каталозі та в профілі автора

Errors: 400, 401

**9. СТОРІНКА МАТЕРІАЛУ** (MVP)

Як студент хочу відкрити сторінку матеріалу, щоб побачити його деталі й завантажити файл.

AC:
- Given існуючий матеріал
- When GET /materials/:id
- Then 200 + title, subject, description, university, course, type, файл, автор, дата, коментарі

Errors: 404

**10. КОМЕНТАРІ** (MVP)

Як студент хочу читати коментарі та залишати власні, щоб оцінити користь матеріалу й допомогти іншим.

AC:
- Given існуючий матеріал
- When GET /materials/:id/comments
- Then 200 + список коментарів (доступно всім)

AC:
- Given користувач, що увійшов, і текст коментаря 1..1000
- When POST /materials/:id/comments
- Then 201 + коментар під матеріалом із датою та нікнеймом автора

Errors: 400, 401, 404

**11. ВИДАЛЕННЯ МАТЕРІАЛУ АДМІНОМ** (MVP)

Як адмін хочу видаляти матеріали, що порушують правила, щоб підтримувати порядок на платформі.

AC:
- Given існуючий матеріал і роль «Адмін» (кнопка видалення на картці видима лише адміну)
- When DELETE /materials/:id
- Then 204 + матеріал зникає з каталогу та профілю автора

Errors: 401, 403, 404

**12. ПРОФІЛЬ КОРИСТУВАЧА** (MVP)

Як користувач хочу мати профіль з аватаркою, нікнеймом і списком моїх матеріалів, щоб бачити свій внесок.

AC:
- Given користувач, що увійшов
- When GET /users/me
- Then 200 + avatar, nickname і список його матеріалів

Errors: 401

**13. ПРОФІЛЬ АДМІНА** (MVP)

Як адмін хочу мати профіль з інструментами модерації, щоб керувати контентом.

AC:
- Given роль «Адмін»
- When GET /users/me
- Then 200 + avatar, nickname, усі матеріали та доступ до перегляду скарг, блокування порушників і видалення матеріалів

Errors: 401, 403

**14. ПОДАННЯ СКАРГИ** (Пізніше)

Як користувач хочу поскаржитися на матеріал, щоб порушення розглянув адмін.

AC:
- Given існуючий матеріал і опис скарги 1..1000 символів
- When POST /reports
- Then 201 + скарга з датою, автором скарги, матеріалом і автором матеріалу

Errors: 400, 401, 404

**15. РОЗГЛЯД СКАРГ І БЛОКУВАННЯ** (Пізніше)

Як адмін хочу переглядати скарги та блокувати порушників, щоб захистити платформу.

AC:
- Given роль «Адмін»
- When GET /reports
- Then 200 + items + total + page

AC:
- Given існуюча скарга й користувач-порушник
- When POST /users/:id/block
- Then 200 + користувач більше не може входити й додавати матеріали

Errors: 401, 403, 404, 409

**16. СПОВІЩЕННЯ** (Пізніше)

Як користувач хочу бачити сповіщення про нові коментарі та результат розгляду скарги, щоб не пропускати важливе.

AC:
- Given користувач, що увійшов
- When GET /notifications (натискання кнопки сповіщень)
- Then 200 + список подій у тимчасовому спливному вікні (порожній список, якщо подій немає)

Errors: 401

**17. AI-ЧАТ-ПОМІЧНИК** (Пізніше)

Як студент хочу поставити запитання AI-помічнику, щоб він допоміг знайти матеріал або з'ясувати навчальне питання.

AC:
- Given користувач, що увійшов, і запитання 1..1000 символів
- When POST /assistant/chat
- Then 200 + відповідь помічника (підказка або список відповідних матеріалів)

Errors: 400, 401

**18. REST API ТА БАЗА ДАНИХ** (MVP)

Як розробник клієнтської частини хочу працювати з REST API, щоб отримувати й зберігати дані системи.

AC:
- Given коректний запит від клієнта
- When запит надходить на endpoint API
- Then відповідь у форматі JSON із кодом 200 / 201 / 204, а зміни зберігаються в базі даних

Errors: 400, 401, 403, 404, 409
